## Potluck 是什么？

Potluck 是一个自托管的模型来源路由器。它对外提供 OpenAI 兼容接口，在受支持的协议之间转换
请求，并把流量发送到用户配置的第三方账户或 API Endpoint。

当前路由能力包括模型组合、轮换优先的路由配置、同模型聚合、并发感知来源选择和尽力而为的
故障切换。实际支持情况取决于提供商、模型、接口和请求类型。

## Potluck 免费吗？

Potluck 源代码采用 MIT 许可证。运行项目仍可能产生服务器、第三方订阅、API 请求、域名、代理
或其他外部服务费用。

Potluck 本身不提供免费模型额度，也不保证第三方试用、促销、订阅权益或模型永久免费、无限量。
请检查第三方当前的服务条款和账单页面。

## 支持哪些提供商和模型？

随着 Potluck 集成和上游服务变化，支持列表也会变化。当前版本仪表盘中显示的连接类型才是
准确信息。连接账户后，可以使用模型选择器或查询：

```bash
curl http://localhost:21023/v1/models \
  -H "Authorization: Bearer YOUR_POTLUCK_API_KEY"
```

模型出现在列表中，并不代表当前账户、地区、额度和所有能力都可用。如果工作流依赖工具调用、
图片、PDF、音频、推理、流式响应或结构化输出，应测试准确的客户端、提供商和模型组合。

## 可以同时使用多个来源吗？

可以。模型组合会把多个模型标识归到同一个名称下，并支持 Fallback、Round Robin 和 Fusion。
路由配置还可以聚合与同一模型族匹配的已配置来源。

只有符合条件的错误才会触发 Fallback。它不能创造配额，也不保证零停机；所有候选都不可用或
不兼容时，请求仍然会失败。详见[模型组合](./features/combos.md)。

## Quota 和 Usage 有什么区别？

**Quota** 会向受支持的第三方查询账户额度信息。只有实现了用量查询的提供商才能显示，具体字段
由第三方决定。

**Usage** 汇总 Potluck 在本地记录的请求，包括可获得的 Token 数和估算成本。估算结果依赖
第三方用量字段和本地价格配置，不是账单。详见[配额与用量](./features/quota-tracking.md)。

## Potluck 会执行预算或发送配额告警吗？

不会。当前项目没有通用的邮件/Webhook 配额告警、支出预测或每日/每月预算强制执行，也不会在
达到消费阈值后自动把流量切换到所谓免费提供商。

财务安全措施应使用第三方自己的消费上限、账单告警和账户控制。

## 应该使用哪个端口？

开发模式、生产模式、Docker 和 CLI 默认都使用端口 `21023`：

```bash
npm run dev
```

客户端应配置为当前实例实际监听的端口：

```text
仪表盘：http://localhost:21023/dashboard
API：   http://localhost:21023/v1
```

## 哪些客户端可以连接 Potluck？

如果客户端正式支持自定义 OpenAI 兼容地址，就可以连接 Potluck。Potluck 当前不宣称已经
验证支持 Cursor 编辑器，因为 Cursor 没有把任意 OpenAI 兼容 Base URL 公开为稳定接口。
客户端行为会变化，请使用仍在维护的集成指南，并测试当前客户端版本：

- [Claude Code](./integration/claude-code.md)
- [Codex](./integration/codex.md)
- [Cline](./integration/cline.md)
- [Continue](./integration/continue.md)
- [Roo Code](./integration/roo.md)
- [其他工具](./integration/other-tools.md)

## 可以自托管 Potluck 吗？

可以。可以直接运行生产构建，也可以使用仓库中的 Dockerfile：

```bash
npm ci
npm run build
PORT=21023 HOSTNAME=0.0.0.0 NODE_ENV=production npm start
```

```bash
docker build -t potluck .
docker run -d --name potluck \
  -p 21023:21023 \
  -v "$HOME/.potluck:/app/data" \
  -e DATA_DIR=/app/data \
  potluck
```

必须使用持久化数据卷。实例可以从网络访问时，应设置非默认仪表盘密码、要求 API Key、通过
可信反向代理提供 HTTPS，并保护 `DATA_DIR`。

## 仪表盘初始密码是什么？

没有配置密码哈希或 `INITIAL_PASSWORD` 时，初始密码为 `123456`，之后可以在仪表盘修改。

不要把仍使用默认密码的实例暴露到互联网。在 **仪表盘 → Endpoint** 中启用端点 API Key
验证；配置 HTTPS 后还应设置：

```env
AUTH_COOKIE_SECURE=true
```

`AUTH_COOKIE_SECURE=true` 需要 HTTPS。

## 数据存储在哪里？

默认情况下，应用数据存储在 `~/.potluck`，也可以通过 `DATA_DIR` 指定其他目录。

重要路径包括：

```text
${DATA_DIR}/db/data.sqlite
${DATA_DIR}/db/backups/
${DATA_DIR}/routing.json
```

整个目录都应视为敏感数据，其中可能包含提供商凭据、设置、API Key、用量历史和请求详情。

## Potluck 会保存提示词或响应吗？

可能会。根据启用的设置和请求路径，用量记录及请求详情日志可能包含客户端请求、转换后的第三方
请求、响应、错误或相关元数据。

不要依赖旧文档中“Potluck 从不存储提示词或响应”的说法。除非确有需要，否则关闭请求正文
日志；检查 Usage/Details 页面，保护数据库备份，并避免在提示词中发送密钥。

## Potluck 会把请求发给所选提供商以外的服务吗？

模型请求会发送到路由实际选择的第三方提供商或 Endpoint。可选功能，例如隧道、更新检查、
OAuth、代理池、Headroom 或其他集成，在配置或调用后可能联系额外服务。

请审查实际启用功能的配置和代码。自托管并不意味着模型请求始终留在本机。

## 如何更新？

首先备份 `DATA_DIR`。源码安装可以使用：

```bash
git pull --ff-only
npm ci
npm run build
PORT=21023 HOSTNAME=0.0.0.0 NODE_ENV=production npm start
```

升级前应阅读版本变更。自行构建容器时，应重新构建镜像并替换容器，同时保留数据卷。
